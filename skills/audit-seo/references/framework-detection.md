# Audit SEO — Framework Detection

Where SEO metadata actually lives per stack, for Code and Combined mode. Detect the
framework from manifests/config at the root before grading anything — the same metadata
export looks different enough between these that guessing produces wrong findings.

## Next.js — App Router

Signal: `app/` directory, `next.config.js`/`.mjs`/`.ts`.

- Static metadata: `export const metadata = { title, description, openGraph, ... }` in
  `layout.tsx`/`page.tsx`.
- Dynamic metadata: `export async function generateMetadata({ params })`.
- Sitemap: `app/sitemap.ts` exporting a `MetadataRoute.Sitemap`.
- Robots: `app/robots.ts` exporting a `MetadataRoute.Robots`.
- Rendering: check for `export const dynamic`, `revalidate`, or a `"use client"` directive
  at the top of the file that owns the main content — a client component with no server
  parent rendering its content is the JS-SEO risk (dimension 6).

## Next.js — Pages Router

Signal: `pages/` directory (no `app/`).

- `next/head`'s `<Head>` component per page, or a shared `_app.tsx`/`_document.tsx` default.
- `getStaticProps`/`getServerSideProps` determine whether content is in the initial HTML;
  a page with neither and no static export is client-rendered.
- `next-sitemap` (a `next-sitemap.config.js`) is the common sitemap/robots generator.

## Astro

Signal: `astro.config.mjs`, `.astro` files.

- Frontmatter + `<head>` block per page/layout; astro renders to static HTML by default
  (server-rendered unless an island opts into client hydration), so dimension 6 findings
  are rarer here — check `client:*` directives on the components that hold primary content.
- `@astrojs/sitemap` integration for sitemap generation.

## Nuxt

Signal: `nuxt.config.ts`.

- `useSeoMeta()` / `useHead()` composables, or the `app.head` key in `nuxt.config.ts` for
  site-wide defaults.
- `@nuxtjs/sitemap` and `@nuxtjs/robots` modules.
- Nuxt defaults to universal (server + client) rendering; `ssr: false` in config means
  client-only — a strong signal to check dimension 6 carefully.

## SvelteKit

Signal: `svelte.config.js`, `src/routes/`.

- `<svelte:head>` block per route for title/meta.
- `export const prerender` / `export const ssr` in `+page.(js|server.js)` determine
  rendering strategy — `ssr = false` is the client-only case.

## Remix / React Router (framework mode)

Signal: `remix.config.js` or `react-router.config.ts` with `app/routes/`.

- `export const meta: MetaFunction` per route.
- Remix/RR7 server-render by default; check for anything disabling that (a fully SPA mode
  config) before assuming SSR is in effect.

## Gatsby

Signal: `gatsby-config.js`.

- `gatsby-plugin-react-helmet` (or React 19's native `<title>`/`<meta>` hoisting) for
  per-page metadata; `gatsby-plugin-sitemap` for sitemap generation. Gatsby is
  static-site-generated by default — dimension 6 findings are rare unless a page opts into
  client-only rendering.

## Rails

Signal: `Gemfile`, `config/application.rb`.

- `content_for :title` / `content_for :meta_description` in views, rendered into
  `<%= yield :title %>` in the layout — or a helper gem (`meta-tags`).
- `sitemap_generator` gem for `sitemap.xml`; `public/robots.txt` is a static file.
- Server-rendered by default (Rails views, or Hotwire/Turbo) — dimension 6 is usually only
  relevant where a page embeds a separate JS SPA (a React/Vue island).

## Hugo / Jekyll (static site generators)

Signal: `config.toml`/`config.yaml` (Hugo), `_config.yml` (Jekyll).

- Front matter (`title:`, `description:`) per content file, rendered into templates via
  `{{ .Title }}` (Hugo) or Liquid tags (Jekyll).
- Output is static HTML at build time — dimension 6 essentially never applies unless the
  theme embeds a separate client-rendered widget for primary content.

## WordPress

Signal: `wp-content/`, `wp-config.php`.

- Yoast SEO or RankMath plugin config (`wp_options` table, or their block-editor panels)
  is almost always the metadata source rather than theme templates directly — check for
  one before assuming metadata is hardcoded in `header.php`.
- `sitemap.xml` is typically generated by the SEO plugin or WordPress core (5.5+) at
  `/wp-sitemap.xml`.

## Plain HTML / no framework detected

Grade directly against the markup in each page's `<head>` and structured-data `<script>`
tags — there's no generator to trace back to, so every finding's evidence is the file
itself.
