# Audit SEO — Output Format

The same markdown is printed in chat and saved to the dated report file. Fill
`assets/audit-report.md`; every section below is required, in this order.

## 1. Header

```markdown
# SEO Audit — <site or repo name>

- **Date:** YYYY-MM-DD
- **Mode:** Live | Code | Combined
- **Scope:** <base URL and/or repo>, N pages sampled
- **Verdict:** 🔴 Blocked | 🟡 At risk | 🟢 Healthy
- **Blockers:** N · **Gaps:** N · **Unverifiable:** N
```

Then one paragraph — three sentences at most — naming the single most damaging finding and
the biggest single win.

## 2. Scorecard

One row per dimension, worst check wins:

```markdown
| # | Dimension | Grade | Worst check | Evidence |
|---|---|---|---|---|
| 1 | Crawlability & indexation | 🔴 | 1.2 noindex on production | `<meta name="robots" content="noindex">` on `/` |
| 2 | On-page metadata | 🟡 | 2.2 meta description missing on 4/6 sampled pages | homepage, `/pricing`, `/blog/a`, `/blog/b` |
| 3 | Content & heading semantics | 🟢 | — | one `<h1>` per sampled page |
...
```

## 3. Work Plan

**This is the deliverable** — the ordered list of fixes, blockers first, then gaps ordered
by how much of the site they touch (`references/audit-workflow.md` → Phase 5).

```markdown
| # | Dim | Grade | Task | Effort | Evidence |
|---|---|---|---|---|---|
| 1 | 1 | 🔴 | Remove `<meta name="robots" content="noindex">` from the production layout (currently applied sitewide) | S | `app/layout.tsx:14` |
| 2 | 4 | 🔴 | Fix malformed JSON-LD on product pages — trailing comma breaks the parse | S | `curl -s <url> \| jq` fails on `<url>/products/example` |
| 3 | 2 | 🟡 | Write unique meta descriptions for the 4 pages sharing the template default | M | homepage, `/pricing`, `/blog/a`, `/blog/b` |
```

Effort: **S** < 1 h · **M** ~ half a day · **L** more than a day.

## 4. Findings by dimension

For each dimension (all eight), every non-🟢 check with its evidence and the concrete fix;
🟢 checks as a single compact line.

```markdown
### 1. Crawlability & indexation — 🔴

- 🔴 **1.2 `noindex` on production** — `<meta name="robots" content="noindex">` present on
  every sampled page, served from the production domain (confirmed not a staging build —
  `curl -sI <url>` shows the production `Host` header). Fix: remove the tag from the shared
  layout; it's the sitewide default rather than a per-page override.
- 🟡 **1.6 One redirect chain over budget** — `/old-page` → `/temp` → `/new-page` (2 hops).
  Fix: point the redirect directly at `/new-page`.
- 🟢 1.1, 1.3, 1.4, 1.5, 1.7
```

## 5. Unverifiable

Every ⚪, each with the exact tool or check a human must run — this is where search volume,
rankings, traffic, and anything needing a signed-in dashboard always land (never fabricated;
`references/rubric.md` → Conservatism rule).

```markdown
- ⚪ **8.1 Search Console verification** — no verification meta tag or DNS record found from
  outside, and not asserted in config. Ask: is this property verified in Google Search
  Console, and can you export the last 90 days of Performance data?
- ⚪ **Keyword rankings / search volume** — not requested; not measurable without Search
  Console, Google Keyword Planner, or a third-party rank tracker. If you want this, run the
  audit alongside an export from one of those tools rather than an estimate from this skill.
```

## 6. Footer

```markdown
---
_Generated by the `audit-seo` skill · mode: Live · 12 pages sampled (sitemap had 340;
sampled by template) · dimensions disabled by config: none · saved to
docs/seo-audits/2026-09-12-full-site.md_
```

The footer must state the mode, how many pages were sampled versus how many exist (when
known), any dimension disabled via config, and the exact saved path.

## Rules

- Verdict is mechanical: any 🔴 → **Blocked**; else any 🟡 → **At risk**; else **Healthy**.
  ⚪ never moves it.
- Work Plan rows map 1:1 to 🔴/🟡 checks — no extra rows, and no padding to look thorough
  when the site is clean (a Healthy verdict with an empty Work Plan is a valid, complete
  report).
- No finding without evidence (`references/rubric.md` → Conservatism rule) — a URL and the
  exact tag/header/status observed, or `file:line` in Code mode.
- No number that wasn't measured. Search volume, rankings, traffic, and competitor data are
  always ⚪ with the tool named — never estimated, even loosely, even when the user asks
  directly (`docs/decision-records/2026-09-12--audit-seo-never-fabricates-search-data.md`).
- Chat output is the full report, then a one-line note naming the saved path, e.g.
  `Saved to docs/seo-audits/2026-09-12-full-site.md (unstaged).`
- The Work Plan describes fixes; it never applies them. Applying a fix is a separate,
  explicit follow-up ask, not part of this skill's default behavior.
